What we are building and why it wins#

Share Radar turns every new NIQ data week into a ranked, explained and verified share brief within minutes, entirely inside Snowflake, and CoCo builds every part of it. It covers the four expected outcomes (automated share reports, anomaly detection, narrative briefs, days-to-minutes). It adds three things a generic entry won't have: an exact share bridge, a real-or-artefact gate, and numbers the LLM cannot get wrong.

The feature set follows five verbs: Detect, Explain, Verify, Anticipate, Act.

Against the rubric

  • Technical (40%): more than ten native features, each doing real work in deployed objects rather than a notebook.

  • Business relevance (35%): it answers "why did share move?" and "is it real?", the two questions that cost client-service time, and sits as the proactive layer under Optiq rather than a copy of it.

  • Completeness (25%): one category end to end on real data, a live replay, measured golden-set accuracy, and a 1–2 page brief.

Four moments for the video that no generic entry will have

  1. Time machine: press Replay, a past week "lands", and the whole chain runs live on real data.

  2. Exact bridge: the waterfall adds up to the reported share change at the second decimal, with no "other" bar.

  3. Artefact catch: a shift caused by a retailer feed change is held back, with the evidence shown.

  4. Unbreakable numbers: we try to make the LLM write a number and the validator blocks it.

HLD: architecture#

Six layers run inside the NIQ Snowflake account, and only the adapter layer knows NIQ's table names. Everything above Anticipate and Narrate is deterministic SQL or Snowflake ML; the LLM only writes words around numbers it is handed.

Each layer maps to a schema (SRC, CORE, APP and ML, SEM, OPS, KB), and each box maps to a ticket in the ticket list and an object in the LLD tab.

HLD: what happens when a data week lands#

A new week (or a replayed one) refreshes the dynamic tables; the stream on the share table fires a triggered task, and SP_RUN_WEEK runs ten steps. Every number is fixed before the LLM is called.

Steps 2 to 9 are set-based SQL or Snowflake ML and are retried independently. A failure in steps 3 (ML part), 7 (TOP_INSIGHTS) or 8 downgrades the brief instead of stopping it; the error matrix in the LLD tab lists each case.

HLD: the Ask-Why agent on CoWork#

One Cortex Agent, SR_DB.SEM.SHARE_RADAR_AGENT, answers follow-up questions in CoWork from the same tables the brief was written from, so chat and brief can never disagree. It never computes a number: every figure comes from a tool result.

Routing rules (in the agent's orchestration instructions)

  1. A "why" question calls get_share_bridge, then check_artefact, before any answer is written.

  2. If check_artefact returns POSSIBLE_DATA_EFFECT, the first sentence says so.

  3. "Who took it" calls share_flow; lever scenarios call what_if, and the answer repeats its assumption.

  4. Any other number goes through share_analyst; definitions go through method_search.

  5. Numbers are quoted exactly as returned, with the period comparison named (for example L4W vs year ago).

  6. A tool error or empty result is reported as such, never filled in.

The agent is added to the CoWork object so analysts find it next to their other agents. The full YAML specification is in the LLD tab.

Assumptions to confirm today (and what we do if wrong)

  1. A1 Weekly facts with at least 104 weeks of history. If fewer: drop year-ago comparisons and use L4W vs prior period only.

  2. A2 Item-level %ACV distribution exists. If not: bridge mode C or D (velocity or mix only); the artefact gate leans on store counts.

  3. A3 Base (non-promoted) sales exist. If not: bridge mode B (distribution, unit velocity, average price) with no separate promo term.

  4. A4 Retailer markets roll up to a parent market. If not: TOP_INSIGHTS replaces the exact retailer split.

  5. A5 Cortex Agents, CoWork, AI_COMPLETE and ML functions are enabled for the team role. If not: Streamlit becomes the only surface and an AI_COMPLETE call answers questions.

  6. A6 We may create notification integrations, or organizers can. If not: the brief stays in-app, plus an emailed export done by hand for the video.

  7. A7 A team database and warehouse exist. If not: the setup DDL in the LLD tab creates them.

  8. A8 One focus manufacturer (the "client") and one category are chosen for the demo; others still compute.

The loop for every ticket

  1. Set the ticket: echo SR-022 > .sr_ticket.

  2. Run /plan with the ticket prompt. CoCo reads AGENTS.md, the skills and the LLD section; a person approves the plan.

  3. CoCo writes only the files the ticket names.

  4. CoCo runs the ticket's named tests (snow sql -f tests/sql/T-BR-01.sql, pytest -q) and fixes until they pass.

  5. The sr-reviewer subagent checks the diff; a person reviews it in the diff view.

  6. Commit as SR-022: <summary> with the trailer Generated-with: CoCo; the Stop hook logs the session.

Keep people on methodology choices, thresholds, golden-set answers and the story. Give CoCo schema discovery (SR-003), DDL, set-based SQL, tests, the Streamlit pages and the agent spec.

How we prove it to judges (Trust page, solution brief and one video clip)

  • Tickets delivered through CoCo, as a count and a share of all tickets.

  • Share of committed lines carrying the Generated-with: CoCo trailer, from git log.

  • Tests written and passing per ticket.

  • Median minutes per ticket, from the session log.

  • A 30-second clip: CoCo turns the SR-022 prompt into the bridge procedure and its tests go green.

CoCo usage draws on AI credits, so ask the organizers whether it counts against the team budget (see Risks).

Capability check — sql/10_src/102_capability.sql. Called at the start of every run; the result caps the bridge mode for that run.

SQL
CREATE TABLE IF NOT EXISTS SR_DB.OPS.CAPABILITY (
  CHECKED_AT       TIMESTAMP_LTZ NOT NULL,
  AS_OF_WEEK       DATE          NOT NULL,
  N_WEEKS          NUMBER        NOT NULL,
  HAS_DIST         BOOLEAN       NOT NULL,
  HAS_UNITS        BOOLEAN       NOT NULL,
  HAS_BASE_VALUE   BOOLEAN       NOT NULL,
  HAS_BASE_UNITS   BOOLEAN       NOT NULL,
  HAS_STORES       BOOLEAN       NOT NULL,
  HAS_UNIVERSE     BOOLEAN       NOT NULL,
  MAX_BRIDGE_MODE  VARCHAR(1)    NOT NULL   -- 'A' | 'B' | 'C' | 'D'
);

CREATE OR REPLACE PROCEDURE SR_DB.APP.SP_CAPABILITY_CHECK()
RETURNS VARCHAR
LANGUAGE SQL
EXECUTE AS CALLER
AS
$$
BEGIN
  INSERT INTO SR_DB.OPS.CAPABILITY
  WITH f AS (
    SELECT * FROM SR_DB.SRC.V_SRC_FACT_WEEKLY
    WHERE WEEK_END_DATE > DATEADD(week, -8, (SELECT MAX(WEEK_END_DATE) FROM SR_DB.SRC.V_SRC_FACT_WEEKLY))
  ), c AS (
    SELECT
      COUNT_IF(ACV_DIST_PCT IS NOT NULL)     / NULLIF(COUNT(*), 0) >= 0.95 AS HAS_DIST,
      COUNT_IF(UNIT_SALES IS NOT NULL)       / NULLIF(COUNT(*), 0) >= 0.95 AS HAS_UNITS,
      COUNT_IF(BASE_VALUE_SALES IS NOT NULL) / NULLIF(COUNT(*), 0) >= 0.95 AS HAS_BASE_VALUE,
      COUNT_IF(BASE_UNIT_SALES IS NOT NULL)  / NULLIF(COUNT(*), 0) >= 0.95 AS HAS_BASE_UNITS,
      COUNT_IF(STORES_SELLING IS NOT NULL)   / NULLIF(COUNT(*), 0) >= 0.95 AS HAS_STORES
    FROM f
  )
  SELECT CURRENT_TIMESTAMP(),
         (SELECT MAX(WEEK_END_DATE) FROM SR_DB.SRC.V_SRC_FACT_WEEKLY),
         (SELECT COUNT(DISTINCT WEEK_END_DATE) FROM SR_DB.SRC.V_SRC_FACT_WEEKLY),
         c.HAS_DIST, c.HAS_UNITS, c.HAS_BASE_VALUE, c.HAS_BASE_UNITS, c.HAS_STORES,
         (SELECT COUNT(*) > 0 FROM SR_DB.INFORMATION_SCHEMA.VIEWS
           WHERE TABLE_SCHEMA = 'SRC' AND TABLE_NAME = 'V_SRC_MARKET_UNIVERSE'),
         CASE WHEN c.HAS_DIST AND c.HAS_BASE_VALUE AND c.HAS_BASE_UNITS THEN 'A'
              WHEN c.HAS_DIST AND c.HAS_UNITS THEN 'B'
              WHEN c.HAS_DIST THEN 'C'
              ELSE 'D' END
  FROM c;
  RETURN 'OK';
END;
$$;

CREATE OR REPLACE DYNAMIC TABLE SR_DB.CORE.DT_PERIOD_WEEK
  TARGET_LAG = DOWNSTREAM
  WAREHOUSE = SR_WH_XS
  REFRESH_MODE = FULL
  COMMENT = 'Week membership of each reporting period, anchored on the latest available week'
AS
WITH asof AS (
  SELECT MAX(WEEK_END_DATE) AS AS_OF_WEEK FROM SR_DB.SRC.V_SRC_FACT_WEEKLY
), def AS (
  SELECT column1 AS PERIOD_CODE, column2 AS FROM_WK, column3 AS TO_WK
  FROM VALUES ('L4W', 3, 0), ('P4W', 7, 4), ('L4W_YA', 55, 52),
              ('L12W', 11, 0), ('L12W_YA', 63, 52), ('L52W', 51, 0), ('L52W_YA', 103, 52)
), weeks AS (
  SELECT DISTINCT WEEK_END_DATE FROM SR_DB.SRC.V_SRC_FACT_WEEKLY
)
SELECT d.PERIOD_CODE,
       w.WEEK_END_DATE,
       a.AS_OF_WEEK,
       DATEADD(week, -d.FROM_WK, a.AS_OF_WEEK) AS PERIOD_START,
       DATEADD(week, -d.TO_WK,   a.AS_OF_WEEK) AS PERIOD_END,
       d.FROM_WK - d.TO_WK + 1                 AS EXPECTED_WEEKS
FROM def d
CROSS JOIN asof a
JOIN weeks w
  ON w.WEEK_END_DATE BETWEEN DATEADD(week, -d.FROM_WK, a.AS_OF_WEEK) AND DATEADD(week, -d.TO_WK, a.AS_OF_WEEK);

Detector (SR-020)#

Noise for each comparison is the standard deviation of the same difference measured on rolling shares in the history before the judged weeks; z = change ÷ noise. L52W comparisons get no z and are gated on points and value only.

SQL
INSERT INTO SR_DB.APP.SHIFT_CANDIDATE
  (RUN_ID, SHIFT_ID, CMP_CODE, MARKET_ID, CATEGORY, MANUFACTURER, BRAND, SH1, SH0, D_SHARE, VALUE_AT_STAKE, Z_SCORE, PASSED_GATES, GATE_NOTES)
WITH roll AS (
  SELECT MARKET_ID, CATEGORY, BRAND, WEEK_END_DATE,
    SUM(VALUE_SALES)     OVER (PARTITION BY MARKET_ID, CATEGORY, BRAND ORDER BY WEEK_END_DATE ROWS BETWEEN 3 PRECEDING AND CURRENT ROW)
    / NULLIF(SUM(CAT_VALUE_SALES) OVER (PARTITION BY MARKET_ID, CATEGORY, BRAND ORDER BY WEEK_END_DATE ROWS BETWEEN 3 PRECEDING AND CURRENT ROW), 0)  AS SH4,
    SUM(VALUE_SALES)     OVER (PARTITION BY MARKET_ID, CATEGORY, BRAND ORDER BY WEEK_END_DATE ROWS BETWEEN 11 PRECEDING AND CURRENT ROW)
    / NULLIF(SUM(CAT_VALUE_SALES) OVER (PARTITION BY MARKET_ID, CATEGORY, BRAND ORDER BY WEEK_END_DATE ROWS BETWEEN 11 PRECEDING AND CURRENT ROW), 0) AS SH12
  FROM SR_DB.CORE.DT_SHARE_WEEK
), diffs AS (
  SELECT MARKET_ID, CATEGORY, BRAND, WEEK_END_DATE,
         SH4  - LAG(SH4, 52)  OVER (PARTITION BY MARKET_ID, CATEGORY, BRAND ORDER BY WEEK_END_DATE) AS D4_YA,
         SH4  - LAG(SH4, 4)   OVER (PARTITION BY MARKET_ID, CATEGORY, BRAND ORDER BY WEEK_END_DATE) AS D4_PP,
         SH12 - LAG(SH12, 52) OVER (PARTITION BY MARKET_ID, CATEGORY, BRAND ORDER BY WEEK_END_DATE) AS D12_YA
  FROM roll
), noise AS (
  SELECT d.MARKET_ID, d.CATEGORY, d.BRAND,
         STDDEV_SAMP(d.D4_YA) AS SD_L4W_VS_YA, STDDEV_SAMP(d.D4_PP) AS SD_L4W_VS_PP, STDDEV_SAMP(d.D12_YA) AS SD_L12W_VS_YA
  FROM diffs d
  WHERE d.WEEK_END_DATE <= DATEADD(week, -4, (SELECT MAX(WEEK_END_DATE) FROM SR_DB.CORE.DT_SHARE_WEEK))
  GROUP BY d.MARKET_ID, d.CATEGORY, d.BRAND
), cfg AS (
  SELECT SR_DB.OPS.CFG('MIN_SHARE_PTS')::FLOAT AS MIN_PTS, SR_DB.OPS.CFG('MIN_VALUE_AT_STAKE')::FLOAT AS MIN_VAL,
         SR_DB.OPS.CFG('MIN_Z')::FLOAT AS MIN_Z, SR_DB.OPS.CFG('COMPARES') AS COMPARES
), z AS (
  SELECT c.*, c.D_SHARE / NULLIF(CASE c.CMP_CODE WHEN 'L4W_VS_YA'  THEN n.SD_L4W_VS_YA
                                                 WHEN 'L4W_VS_PP'  THEN n.SD_L4W_VS_PP
                                                 WHEN 'L12W_VS_YA' THEN n.SD_L12W_VS_YA END, 0) AS Z_SCORE
  FROM SR_DB.CORE.DT_SHARE_COMPARE c
  LEFT JOIN noise n ON n.MARKET_ID = c.MARKET_ID AND n.CATEGORY = c.CATEGORY AND n.BRAND = c.BRAND
  WHERE c.D_SHARE IS NOT NULL AND c.MARKET_ID IN (<scope markets>)
)
SELECT :P_RUN_ID,
       MD5(:P_RUN_ID || '|' || z.CMP_CODE || '|' || z.MARKET_ID || '|' || z.CATEGORY || '|' || z.BRAND),
       z.CMP_CODE, z.MARKET_ID, z.CATEGORY, z.MANUFACTURER, z.BRAND, z.SH1, z.SH0, z.D_SHARE, z.VALUE_AT_STAKE, z.Z_SCORE,
       ABS(z.D_SHARE) * 100 >= cfg.MIN_PTS AND ABS(z.VALUE_AT_STAKE) >= cfg.MIN_VAL
         AND (z.Z_SCORE IS NULL OR ABS(z.Z_SCORE) >= cfg.MIN_Z)                              AS PASSED_GATES,
       OBJECT_CONSTRUCT('pts', ABS(z.D_SHARE) * 100, 'value', ABS(z.VALUE_AT_STAKE), 'z', z.Z_SCORE)  AS GATE_NOTES
FROM z CROSS JOIN cfg

Where it happened (SR-023, exact part)#

L11 Streamlit app#

One codebase deploys as two Streamlit in Snowflake apps on the warehouse runtime. SR_DB.APP.SHARE_RADAR is the read-only app that analysts and judges open; it is owned by the read-only role SR_UI (added in L12). SR_DB.APP.SHARE_RADAR_ADMIN adds the replay controls and the Settings page; it is owned by SR_APP, and only the team can open it. Apps run with their owner's rights: the owner role, not the viewer's role, decides what an app can read or change. That is why the admin controls live in a separate app guarded by a grant, not behind an if in the code.

Four rules follow from the owner's-rights model:

  • The app never runs pipeline steps itself. A warehouse-runtime app runs as an owner's-rights stored procedure, and the steps set the query tag with ALTER SESSION, which owner's-rights code cannot do. The admin app starts work with EXECUTE TASK and watches OPS.RUN_LOG and OPS.STEP_LOG. A task with no schedule runs only when someone executes it, and a suspended task can be executed without resuming it.

  • No SHOW or DESCRIBE in app code. Read our own tables, or INFORMATION_SCHEMA table functions.

  • CURRENT_USER() needs READ SESSION on the owner role (row access in Streamlit). Until it is granted, viewer_name() returns None and the sidebar says "viewer unknown".

  • Caching is per viewer session on the warehouse runtime (limitations), so st.cache_data saves repeat queries within one visit, not across viewers.

  CATEGORY       VARCHAR    NOT NULL,      -- category or '*'

CREATE OR REPLACE PROCEDURE SR_DB.OPS.SP_ENTITLE(P_TYPE VARCHAR, P_PRINCIPAL VARCHAR, P_CATEGORY VARCHAR, P_MARKET_ID VARCHAR)
RETURNS NUMBER
LANGUAGE SQL
EXECUTE AS CALLER
AS
$$
BEGIN
  MERGE INTO SR_DB.OPS.ENTITLEMENT t
  USING (
    SELECT UPPER(:P_TYPE) AS PRINCIPAL_TYPE, UPPER(:P_PRINCIPAL) AS PRINCIPAL, :P_CATEGORY AS CATEGORY, :P_MARKET_ID AS MARKET_ID
    UNION

END;
$$;

How a run handles failure (python/sr_lib/run.py). Step procedures do not catch their own errors. run_week catches each step's error. A critical step closes the run as FAILED; an optional one logs WARN and carries on. An outer handler makes sure no run is left RUNNING, and the 30-minute busy window stops a crashed run from blocking replay for ever. log_step gains a started_at keyword argument.

Python
import json
from datetime import datetime, timezone
from snowflake.snowpark import Session
from snowflake.snowpark.exceptions import SnowparkSQLException

OPTIONAL_COST_STEPS = {"ML_ANOMALY", "TOP_INSIGHTS"}

def run_week(session: Session, trigger_type: str = "MANUAL", force: bool = False) -> str:
    run_id = open_run(session, trigger_type, force)           # None: a SKIPPED row is already written (E16)
    if run_id is None:
        return "SKIPPED"
    try:
        cap = float(session.sql("SELECT SR_DB.OPS.CFG('MAX_CREDITS_PER_RUN')::FLOAT").collect()[0][0])
        for step_no, name, sql, critical in STEPS:
            started = datetime.now(timezone.utc)
            if name in OPTIONAL_COST_STEPS and estimate_credits(session, run_id) > cap:      # E09
                log_step(session, run_id, step_no, name, "SKIPPED", None, "credit cap", started_at=started)
                continue
            try:
                result = session.sql(sql.format(run=run_id)).collect()[0][0]
                rows = result if isinstance(result, int) else None   # SP_CAPABILITY_CHECK returns 'OK'
                log_step(session, run_id, step_no, name, "OK", rows, None, started_at=started)
            except SnowparkSQLException as e:
                msg = f"{name}: {e.message}"[:2000]
                log_step(session, run_id, step_no, name, "FAILED" if critical else "WARN", None, msg, started_at=started)
                if critical:
                    close_run(session, run_id, "FAILED", msg)
                    return run_id
        close_run(session, run_id, "SUCCEEDED", None)
    except Exception as e:                                       # a bug in this file, not in a step
        close_run(session, run_id, "FAILED", f"INTERNAL: {e}"[:2000])
    return run_id

APP.SP_RESOLVE(P_KIND VARCHAR, P_TEXT VARCHAR, P_CMP_CODE VARCHAR) RETURNS VARIANT resolves names for all tools. Its candidates are the distinct brands (or market names and IDs) in SEM.V_TOOL_BRIDGE for that comparison, so the row policy already applies. The score is 0 for an exact case-insensitive match on name or ID; 1 when the name contains the input and the input has at least 3 characters; otherwise EDITDISTANCE(UPPER(name), UPPER(input)). If the best score is 2 or less and unique, it returns {"status": "OK", "value": …, "name": …}. If the best score is 2 or less but tied, it returns {"status": "AMBIGUOUS", "what": …, "candidates": […]}. Otherwise it returns {"status": "NOT_FOUND", "what": …, "input": …, "candidates": [the three closest names]}.

RETURNS VARCHAR

$$

  m   VARIANT;

Credit estimate during a run. The estimate guards MAX_CREDITS_PER_RUN (E09) and fills RUN_LOG.CREDITS_EST. It reads the run's own session history, so it needs no extra privilege, and it counts execution time at the standard warehouse rates. It overstates a little, because it ignores concurrency, which is the safe side for a cap. If the account uses Gen2 warehouses, set the rates from that account's price sheet. AI tokens are billed separately and are reported, not estimated.

Python
# python/sr_lib/run.py
CREDITS_PER_HOUR = {"X-Small": 1, "Small": 2, "Medium": 4, "Large": 8}

def estimate_credits(session: Session, run_id: str) -> float:
    rows = session.sql(
        """SELECT WAREHOUSE_SIZE, SUM(EXECUTION_TIME) / 1000 / 3600 AS HOURS
           FROM TABLE(INFORMATION_SCHEMA.QUERY_HISTORY_BY_SESSION(RESULT_LIMIT => 10000))
           WHERE QUERY_TAG LIKE ? AND WAREHOUSE_SIZE IS NOT NULL
           GROUP BY WAREHOUSE_SIZE""", params=[f"SR|run={run_id}|%"]).collect()
    return round(sum(CREDITS_PER_HOUR.get(r["WAREHOUSE_SIZE"], 4) * float(r["HOURS"]) for r in rows), 4)

RETURNS NUMBER

$$
DECLARE
  t TIMESTAMP_LTZ DEFAULT CURRENT_TIMESTAMP();
BEGIN
  DELETE FROM SR_DB.OPS.HEALTH_LOG WHERE CHECKED_AT < DATEADD(day, -14, CURRENT_TIMESTAMP());

  INSERT INTO SR_DB.OPS.HEALTH_LOG                                   -- latest refresh of each dynamic table
  SELECT :t, 'DYNAMIC_TABLE', NAME, IFF(STATE IN ('FAILED', 'UPSTREAM_FAILED'), 'FAILED', 'OK'), OBJECT_CONSTRUCT(*)
  FROM TABLE(SR_DB.INFORMATION_SCHEMA.DYNAMIC_TABLE_REFRESH_HISTORY(NAME_PREFIX => 'SR_DB.CORE.', RESULT_LIMIT => 1000))
  WHERE STATE NOT IN ('SCHEDULED', 'EXECUTING')
  QUALIFY ROW_NUMBER() OVER (PARTITION BY NAME ORDER BY REFRESH_START_TIME DESC) = 1;

  SHOW TASKS IN SCHEMA SR_DB.OPS;                                    -- the triggered and hourly tasks must be started
  INSERT INTO SR_DB.OPS.HEALTH_LOG
  SELECT :t, 'TASK', "name", IFF("name" IN ('T_RUN_WEEK', 'T_HEALTH') AND "state" <> 'started', 'FAILED', 'OK'),
         OBJECT_CONSTRUCT('state', "state", 'schedule', "schedule")
  FROM TABLE(RESULT_SCAN(LAST_QUERY_ID()));

  INSERT INTO SR_DB.OPS.HEALTH_LOG                                   -- last finished run of each task
  SELECT :t, 'TASK_RUN', NAME, IFF(STATE = 'FAILED', 'WARN', 'OK'),
         OBJECT_CONSTRUCT('state', STATE, 'error', ERROR_MESSAGE, 'completed', COMPLETED_TIME)
  FROM TABLE(SR_DB.INFORMATION_SCHEMA.TASK_HISTORY(RESULT_LIMIT => 1000))
  WHERE SCHEMA_NAME = 'OPS' AND STATE IN ('SUCCEEDED', 'FAILED', 'CANCELLED', 'SKIPPED')
  QUALIFY ROW_NUMBER() OVER (PARTITION BY NAME ORDER BY COMPLETED_TIME DESC) = 1;

  SHOW STREAMS IN SCHEMA SR_DB.OPS;
  INSERT INTO SR_DB.OPS.HEALTH_LOG
  SELECT :t, 'STREAM', "name",
         CASE WHEN "stale"::VARCHAR = 'true' THEN 'FAILED'
              WHEN "stale_after" < DATEADD(day, 2, CURRENT_TIMESTAMP()) THEN 'WARN' ELSE 'OK' END,
         OBJECT_CONSTRUCT('stale', "stale", 'stale_after', "stale_after")
  FROM TABLE(RESULT_SCAN(LAST_QUERY_ID()));

  SHOW ALERTS IN SCHEMA SR_DB.OPS;
  INSERT INTO SR_DB.OPS.HEALTH_LOG
  SELECT :t, 'ALERT', "name", IFF("state" <> 'started', 'FAILED', 'OK'), OBJECT_CONSTRUCT('state', "state")
  FROM TABLE(RESULT_SCAN(LAST_QUERY_ID()));

  INSERT INTO SR_DB.OPS.HEALTH_LOG                                   -- a weekly product should not go 8 days silent

END;
$$;

Tests that expect an error. Security tests switch to the role under test and try each forbidden statement inside its own BEGIN … EXCEPTION block. # Share Radar: rules for CoCo

## What this repository builds
Share Radar watches NIQ retail measurement data each week. It finds material competitive share shifts,
explains each one with an exact driver bridge, checks whether it could be a data artefact, publishes a
numbers-locked brief, and answers follow-up questions through a Cortex Agent in CoWork. The full design is
in docs/design.md, exported from the team doc. Section numbers (L1 to L14, T1 to T7) refer to it.

## Golden rules
1. One ticket at a time. The current ticket ID is in .sr_ticket. Touch only that ticket's files and tests (T7).
2. Names in the design are final: objects, columns, settings, files and test IDs. If one looks wrong, stop and
   ask. Never rename on your own.
3. Fully qualify every object as SR_DB.<SCHEMA>.<OBJECT>.
4. Thresholds come from OPS.SETTINGS through SR_DB.OPS.CFG('<KEY>'), never as literals. Inside dynamic tables,
   read OPS.SETTINGS with a scalar subquery instead.
5. Only sql/10_src/101_adapter_views.sql names NIQ objects.

# Share methodology

## Definitions
- %ACV distribution of an item: the share of all-commodity volume in stores selling it, 0 to 100.
- TDP (total distribution points) = sum of item %ACV; over a period, also summed across weeks.
- Value share = brand value sales / category value sales, within one market, category and period.
  Shares never add up or average across markets.
- Velocity = sales per TDP point. Price = value per unit. Promo index = actual value / base value.

## The bridge (L6)
- share = distribution share x velocity index x price index x promo index (mode A), each relative to the category.
- Points per term = 100 x L(s1, s0) x ln(F1 / F0), where L(a, b) = (a - b) / (ln a - ln b) and L(a, a) = a.
  The terms add up exactly to the change, so the residual is zero.
- Mode A: TDP, base units, base value, value -> four terms. Mode B: TDP, units, value -> distribution, unit
  velocity, price. Mode C: TDP, value -> distribution, value velocity. Mode D: no terms.
- NEW, EXIT and NO_DATA rows get no terms.

## Where and who
- Retailer split, exact: performance = average weight x change in within-retailer share;
  mix = average share x change in weight.
- Flow: a losing brand's points go to gainers in proportion to their gains. It is an accounting allocation;
  never call it switching.

## Early warning
- If the latest week's distribution share persists, next period's L4W share moves by about
  s(L4W) x (DS latest / DS L4W - 1), other levers held. It is mechanical, not a forecast.

## Data artefact rules (L6)
- R1 coverage, R2 feed, R3 restatement, R4 recode, R5 spike, R6 gap.
- Any HIGH rule -> POSSIBLE_DATA_EFFECT, held back from the brief. MEDIUM only -> MIXED.

## Writing about it
- Name the comparison every time, for example "last 4 weeks vs year ago". Put the largest term first.
- Say "share points" for changes, never "percent". Never state a number that no tool or fact returned.

Python
#!/usr/bin/env python3
"""Share Radar CoCo session log.

stop    Stop hook: record the ticket, changed files, lines added and tests touched, if the tree changed.
human   A person edited CoCo's output by hand: always record, with HUMAN_EDITS = true.
manual  Work done where hooks do not fire (for example CoCo in Snowsight): always record.
flush   Load records not yet loaded into SR_DB.OPS.COCO_LOG.

Never blocks CoCo: every failure goes to stderr and the exit code is 0.
"""
from __future__ import annotations

import argparse
import base64
import hashlib
import json
import os
import subprocess
import sys
from datetime import datetime, timezone
from pathlib import Path

ROOT = Path(__file__).resolve().parents[1]
LOG_MD = ROOT / "docs" / "coco_log.md"
LOG_JSONL = ROOT / "docs" / "coco_log.jsonl"
STATE = ROOT / ".git" / "sr_coco_state.json"          # last diff hash and number of lines loaded
TICKET_FILE = ROOT / ".sr_ticket"
CONNECTION = os.environ.get("SR_CONNECTION", "sr")
MD_HEADER = ("| Logged (UTC) | Ticket | Surface | Event | Files | Lines added | Tests touched | Human edits | Note |\n"
             "| --- | --- | --- | --- | --- | --- | --- | --- | --- |\n")

def git(*args: str) -> str:
    return subprocess.run(["git", *args], cwd=ROOT, capture_output=True, text=True, check=False).stdout

def current_ticket() -> str:
    return TICKET_FILE.read_text(encoding="utf-8").strip() if TICKET_FILE.exists() else "SR-???"

def changed_files() -> tuple[list[str], int, str]:
    """Files changed against HEAD, lines added, and a hash of the numstat used to skip unchanged trees."""
    numstat = git("diff", "--numstat", "HEAD")
    files, added = [], 0
    for line in numstat.splitlines():
        parts = line.split("\t", 2)
        if len(parts) == 3:
            files.append(parts[2])
            added += int(parts[0]) if parts[0].isdigit() else 0
    return files, added, hashlib.sha1(numstat.encode()).hexdigest()

def tests_touched(files: list[str]) -> list[str]:
    return sorted(Path(f).stem for f in files if f.startswith(("tests/sql/T-", "python/tests/test_")))

def read_state() -> dict:
    return json.loads(STATE.read_text()) if STATE.exists() else {"diff_hash": "", "loaded": 0}

def write_state(state: dict) -> None:
    STATE.write_text(json.dumps(state))

def hook_input() -> dict:
    """The hook passes a JSON object on stdin; manual calls have none."""
    if sys.stdin is None or sys.stdin.isatty():
        return {}
    try:
        return json.loads(sys.stdin.read() or "{}")
    except json.JSONDecodeError:
        return {}

def record(row: dict) -> None:
    LOG_MD.parent.mkdir(parents=True, exist_ok=True)
    if not LOG_MD.exists():
        LOG_MD.write_text("# CoCo session log\n\n" + MD_HEADER, encoding="utf-8")
    with LOG_MD.open("a", encoding="utf-8") as md:
        md.write(f"| {row['logged_at']} | {row['ticket']} | {row['surface']} | {row['event']} | {len(row['files'])} | "
                 f"{row['lines_added']} | {', '.join(row['tests']) or '-'} | {'yes' if row['human_edits'] else 'no'} | "
                 f"{row['note'].replace('|', '/')} |\n")
    with LOG_JSONL.open("a", encoding="utf-8") as js:
        js.write(json.dumps(row) + "\n")

def flush(state: dict) -> None:
    lines = LOG_JSONL.read_text(encoding="utf-8").splitlines() if LOG_JSONL.exists() else []
    new = [json.loads(x) for x in lines[state["loaded"]:]]
    if not new:
        return
    payload = base64.b64encode(json.dumps(new).encode("utf-8")).decode("ascii")
    sql = ("INSERT INTO SR_DB.OPS.COCO_LOG (LOGGED_AT, TICKET, SURFACE, FILES, LINES_ADDED, TESTS, HUMAN_EDITS, NOTE) "
           "SELECT f.value:logged_at::TIMESTAMP_LTZ, f.value:ticket::VARCHAR, f.value:surface::VARCHAR, f.value:files, "
           "f.value:lines_added::NUMBER, f.value:tests, f.value:human_edits::BOOLEAN, f.value:note::VARCHAR "
           f"FROM TABLE(FLATTEN(INPUT => PARSE_JSON(BASE64_DECODE_STRING('{payload}')))) f")
    res = subprocess.run(["snow", "sql", "-q", sql, "-c", CONNECTION], capture_output=True, text=True, check=False)
    if res.returncode == 0:
        state["loaded"] = len(lines)
    else:
        print(f"coco_log: load failed, will retry next flush: {res.stderr.strip()[:300]}", file=sys.stderr)

def main(event: str, surface: str = "cli", note: str = "") -> int:
    try:
        state = read_state()
        if event == "flush":
            flush(state)
        else:
            files, added, diff_hash = changed_files()
            if event == "stop" and diff_hash == state["diff_hash"]:
                return 0                                   # nothing changed since the last record
            hook = hook_input() if event == "stop" else {}
            record({
                "logged_at": datetime.now(timezone.utc).isoformat(timespec="seconds"),
                "ticket": current_ticket(), "surface": surface, "event": event,
                "files": files, "lines_added": added, "tests": tests_touched(files),
                "human_edits": event == "human",
                "note": (note or str(hook.get("session_id", "")))[:500],
            })
            state["diff_hash"] = diff_hash
        write_state(state)
    except Exception as exc:                               # the hook must never stop CoCo
        print(f"coco_log: {exc}", file=sys.stderr)
    return 0

if __name__ == "__main__":
    parser = argparse.ArgumentParser()
    parser.add_argument("--event", choices=["stop", "human", "manual", "flush"], required=True)
    parser.add_argument("--surface", choices=["cli", "desktop", "snowsight"], default="cli")
    parser.add_argument("--note", default="")
    args = parser.parse_args()
    sys.exit(main(args.event, args.surface, args.note))
